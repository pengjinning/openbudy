## 二、技术方案

### 2.1 Docusaurus 站点放置方式（待确认 ⚠️）

推荐 **方案 A**（下文默认按 A 规划）：

- **方案 A（推荐）**：`docs/` 作为独立的 pnpm 子包，内含完整 Docusaurus 站点：

  ```text
  docs/
  ├── package.json          # 独立依赖：@docusaurus/core、preset-classic 等
  ├── docusaurus.config.ts
  ├── sidebars.ts
  ├── docs/                 # 教程正文（Markdown）
  │   ├── intro/
  │   ├── electron/
  │   ├── llm/
  │   ├── tools/
  │   ├── agent-loop/
  │   └── advanced/
  └── src/                  # 主题微调、自定义组件（如需）
  ```

  - 优点：与 Electron 应用依赖完全隔离（Docusaurus 与 Vite/React 19 的依赖不会互相污染），根目录保持干净。
  - 根目录 `package.json` 增加快捷脚本：`docs:dev`、`docs:build`（内部 `pnpm --filter` 或 `cd docs && ...`）。

- **方案 B**：根目录直接放 `docusaurus.config.ts`，`docs/` 仅存 Markdown 内容。
  - 缺点：Docusaurus 依赖需并入主 `package.json`，与 Electron/Vite 依赖树混合，构建链互相干扰，不推荐。

### 2.2 版本与构建

- Docusaurus **3.x**（支持 TypeScript 配置、MDX）。
- Node ≥ 22（项目 `.nvmrc` 已满足）。
- 命令：`docs:dev`（本地 3000 端口热更新预览）、`docs:build`（产出静态站点到 `docs/build`）。
- `.gitignore` 追加：`docs/node_modules/`、`docs/build/`。

### 2.3 配置要点

- `i18n` 默认中文；站点名「OpenBudy Agent 实战」。
- 侧边栏按「篇 → 章」两级组织，启用 `autogenerated` + 手动排序。
- 代码块统一 `ts` / `tsx` / `bash` 高亮；关键章节嵌入 Mermaid 流程图（Docusaurus 原生支持）。
- 保留现有 [docs/readme.md](../docs/readme.md)（重定向到教程首页，或合并进 intro）。

## 三、教程章节大纲（共 5 篇 14 章）

> 每章结构固定为：**概念讲解（是什么/为什么）→ 仓库代码精读（贴真实代码）→ 动手实战（改代码/跑起来）→ 小结与思考题**。

### 第一篇 · 准备篇：认识 Agent 与项目全貌

**第 1 章 · 什么是 AI Agent**

- 从 Chatbot 到 Agent：LLM + 工具调用 + 循环 = 自主执行
- OpenBudy 的能力演示：自然语言 → 自主规划 → 执行工具 → 交付结果
- 核心概念速览：LLM / Tool / Agent Loop / IPC / Sandbox（各一句话 + 后文章节索引）

**第 2 章 · 项目架构与开发环境**

- 三大模块架构图：`electron/`（主进程）↔ `src/`（渲染进程 React）↔ `agent-core/`（Agent 引擎）
- 技术栈一览（Electron 30 / React 19 / AntD 6 / Zustand / Vite / Dexie / pi-ai）
- 实战：克隆仓库、`pnpm install`、`pnpm electron:dev` 跑起来；申请智谱 API Key 并配置

### 第二篇 · Electron 基础篇

**第 3 章 · Electron 进程模型与窗口**

- 主进程 / 渲染进程 / preload 脚本三者的职责与安全模型（为什么 Node 能力不直接暴露给页面）
- 逐行精读 [electron/main.ts](../electron/main.ts)：`BrowserWindow` 创建、contextIsolation、Vite 集成（`vite-plugin-electron` 如何同时构建两端）
- 实战：在窗口里渲染第一个 React 页面

**第 4 章 · IPC 通信（一）：请求-响应模式**

- `ipcMain.handle` + `ipcRenderer.invoke`：Promise 风格的双向通信
- 精读 [electron/ipc/storage.ts](../electron/ipc/storage.ts)（配置读写 `~/.openbudy/config.json`）与 [electron/ipc/file.ts](../electron/ipc/file.ts)（文件读写 / 目录选择 / `shell.openPath`）
- 精读 [electron/preload.ts](../electron/preload.ts)：`contextBridge.exposeInMainWorld` 如何以白名单方式暴露 `window.electronAPI`
- 实战：新增一个自己的 IPC 通道（如 `app:getVersion`）

**第 5 章 · IPC 通信（二）：事件推送模式**

- `webContents.send` + `ipcRenderer.on`：主进程主动推送（`agent:event` 流式事件就靠它）
- 精读 [src/services/ipc.ts](../src/services/ipc.ts)：类型安全的 `ElectronAPI` 封装 + **浏览器 Mock 模式**（`pnpm dev` 无 Electron 也能调试 UI）
- 实战：写一个「主进程每秒推送计数 → 渲染进程实时显示」的最小示例

### 第三篇 · LLM 与工具篇

**第 6 章 · LLM API 基础与 pi-ai**

- 消息协议：`system / user / assistant / tool` 四种 role 与 `tool_calls` 字段
- 什么是流式输出（SSE / chunk）
- pi-ai 是什么：Provider / Model / `streamSimple` 的抽象设计；为什么用它而不是裸写 fetch
- 精读 [agent-core/llm/pi-ai.ts](../agent-core/llm/pi-ai.ts)：`ModelConfig` → pi-ai `Model` 的转换、智谱 GLM 预设（[deepseek-presets.ts](../agent-core/llm/deepseek-presets.ts)）、`baseUrl` 规范化
- 实战：30 行代码接通智谱 GLM，在终端跑出第一段流式回复

**第 7 章 · 工具调用（Tools）**

- Function Calling 原理：模型不执行代码，只「报菜名」——由宿主执行并把结果回填
- 工具三要素：`ToolDefinition`（JSON Schema 声明）+ `ToolHandler`（实现）+ `ToolExecutionContext`（工作区路径、取消信号）
- 精读五个内置工具：[shell.ts](../agent-core/tools/shell.ts)、[file-read.ts](../agent-core/tools/file-read.ts)、[file-write.ts](../agent-core/tools/file-write.ts)、[web-search.ts](../agent-core/tools/web-search.ts)、[web-fetch.ts](../agent-core/tools/web-fetch.ts)
- 精读注册中心 [agent-core/tools/registry.ts](../agent-core/tools/registry.ts)：注册 / 注销 / 统一 execute
- 实战：动手写一个新工具 `current_time` 并注册，观察模型何时调用它

### 第四篇 · Agent Loop 篇（核心）

**第 8 章 · Agent Loop：从对话到自主执行**

- 核心循环伪代码：`while → LLM(带 tools) → 有 tool_calls？→ 执行 → 结果回填 messages → 继续`
- 精读 [agent-core/loop.ts](../agent-core/loop.ts) 全流程：
  - 消息构建：系统提示词（[planner.ts](../agent-core/planner.ts) 的 `buildAgentSystemPrompt`）+ 历史消息转换 `historyToLLMMessages`
  - 流式处理：`text_delta` / `tool_call` / `done` 三类 chunk
  - 工具结果如何以 `role: 'tool'` 回填
- Mermaid 时序图：用户消息 → Loop 迭代 → 工具执行 → 事件推送 UI

**第 9 章 · 事件驱动：让 Agent 的思考过程可见**

- `AgentEvent` 事件体系（status_change / thinking / text_delta / tool_call / tool_result / task_complete / error）
- 精读 [electron/ipc/agent.ts](../electron/ipc/agent.ts)：`agent:execute`（invoke）与 `agent:event`（推送）如何配合；`AbortController` 实现任务取消
- 渲染端消费：[src/hooks/useAgent.ts](../src/hooks/useAgent.ts) 订阅事件 → Zustand store（[chatStore.ts](../src/stores/chatStore.ts)）→ 消息气泡 / [ToolCallCard.tsx](../src/components/chat/ToolCallCard.tsx) 渲染
- 实战：给事件流新增一种「耗时统计」展示

**第 10 章 · 安全沙箱与护栏**

- 为什么必须做沙箱：模型输出的命令/路径不可信
- 精读 [agent-core/sandbox.ts](../agent-core/sandbox.ts)：路径越界校验 `validatePath` + 13 条危险命令黑名单
- 精读 [agent-core/executor.ts](../agent-core/executor.ts)：执行前的双重防御；[monitor.ts](../agent-core/monitor.ts)：迭代上限（30 次）与超时
- 实战：尝试让 Agent 执行 `rm -rf /`，观察被拦截的完整链路

### 第五篇 · 综合与进阶篇

**第 11 章 · 全链路串讲：一次任务的完整旅程**

- 端到端时序图：`ChatInput` → `useAgent` → IPC → 主进程 Loop → 工具 → 事件回推 → UI 更新
- 本地持久化：Dexie（[src/services/db.ts](../src/services/db.ts)）存任务与消息；右侧结果面板（文件树 / Diff）
- 动手：跟随 3 个完整案例走完全流程（① 写文件并打开 ② 搜索网页并总结 ③ 跑 shell 命令并修复报错）

**第 12 章 · 扩展开发：定制你的 Agent**

- 实战 1：新增自定义工具（完整步骤清单）
- 实战 2：接入 DeepSeek（[deepseek-presets.ts](../agent-core/llm/deepseek-presets.ts)）与任意 OpenAI 兼容服务
- 实战 3：调整系统提示词改变 Agent 行为风格

**第 13 章 · 打包、调试与最佳实践**

- electron-builder 打包（[electron-builder.yml](../electron-builder.yml)）；`pnpm lint` 类型检查
- 调试技巧：DevTools、主进程日志、浏览器 Mock 模式
- 常见坑与最佳实践清单（IPC 安全、Key 不进渲染进程、流式 UI 卡顿等）

**第 14 章 · 展望与学习路径**

- 下一步方向：MCP 协议、子代理（sub-agent）、记忆与上下文压缩、人工确认门控
- 延伸阅读与社区资源
